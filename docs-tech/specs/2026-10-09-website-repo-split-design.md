# Website repository split

Type: explanation + scope. Source: the session of 2026-10-09; every decision below was taken with the maintainer. It
runs **after P5** (`2026-10-01-website-redesign-design.md` § Delivery): P4 → P5 → split.

## Outcome

The website (`openwhistle.net`, its documentation and its image) lives in `openwhistle/website`, independent of the
software's source. The software repository keeps the code, its tests and `docs-tech/` for the code. Documentation
drift is held off by a rule in both `CLAUDE.md` files and by the website build, which fails when the documentation
no longer matches the latest release.

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| S-1 | Repository `openwhistle/website` in the organisation | Maintainer's choice; matches the image `ghcr.io/openwhistle/website` |
| S-2 | After P5, never before | GitHub Pages and the custom domain then never move between repositories; P5 has switched Pages off |
| S-3 | The files move with their history (`git filter-repo` on a fresh clone) | `git log`/`blame` of every page and test stays readable; the sitemap's `lastmod` keeps its dates |
| S-4 | The website build reads the **latest release tag** of `openwhistle/OpenWhistle`, not `main` | The documentation describes what one can install, not unreleased work |
| S-5 | `app/config.py` from that tag is parsed with `ast`, never imported | No dependency on the app's packages; a `Settings` field missing from `config.yml` (or stale there) fails the build |
| S-6 | Drift rule in both `CLAUDE.md` files; plus the website workflow runs weekly | Maintainer's choice (the rule); the weekly run turns a release without its documentation red within a week |
| S-7 | Shared assets are copied, and the website build compares them with the release tag | The app image stops reading `docs/fonts`; one logo geometry stays one geometry |

## What moves, what stays

| Moves to `openwhistle/website` | Stays in `openwhistle/OpenWhistle` |
| --- | --- |
| `docs/` (all published sources, `_data`, `_layouts`, fonts, images, diagram sources of the site) | `app/`, its tests, `Dockerfile`, compose files, Helm, Ansible role |
| `website/` (P4: nginx.conf, Dockerfile) | `docs-tech/` for the code (specs and plans of the software) |
| `scripts/build_site.py`, `render_changelog.py`, `package_site.py`, `site_stats.py`, `check_external_links.py` | `scripts/render_diagrams.py` for `docs-tech/_diagrams` (the website gets its own copy, same pinned draw.io image) |
| Site tests: `tests/built_site.py` and every test that reads it or `docs/` without importing `app` (the plan lists them), `tests/website/`, the site e2e modules | The app's e2e tests, `tests/e2e/conftest.py`'s app fixtures |
| `website-image.yml`, `links.yml`; the site's mutation specs | `ci.yml`, `e2e.yml`, `security.yml`, `docker-publish.yml`, the app's mutation specs |
| `docs-tech/` parts about the site: website specs and plans, `seo-marketing.md`, `website-image.md`, the site half of `local-review.md`, `DESIGN.md`'s site rules | `DESIGN.md` for the app (the website gets the site part) |

The plan derives the exact test list by script (a test moves if it imports `tests.built_site` or reads `docs/` and does
not import `app`), so no test is lost and none is duplicated.

## Coupling after the split

| Coupling today | After |
| --- | --- |
| Changelog page from `CHANGELOG.md` | fetched from the release tag at build |
| Configuration reference ↔ `Settings`, both directions | `app/config.py` of the tag parsed (S-5); mismatch fails the build |
| "Current version" = `app_version` | from the tag |
| Status workflow ↔ `ReportStatus`, admin routes in the admin guide | the same parse of the tag's source; mismatch fails the build |
| App image copies `docs/fonts` | the app gets its own `app/static/fonts/`; the website build checks the tag's font files are byte-identical to `docs/fonts` (S-7) |
| `docs/favicon.svg` = `app/static/favicon.svg`, one mark geometry (`tests/test_mark.py`) | `tests/test_mark.py` stays in the app for its own files; the website build compares its copy with the tag's |
| Screenshots generated by the app | the app's screenshot script writes into a checkout of the website repository given by path |
| Docs, README and compose in one commit | `CLAUDE.md` rule: a user-facing change in the app gets a pull request in `openwhistle/website` in the same piece of work, linked from the app's pull request |
| Demo footer links to the imprint and privacy policy | unchanged (URLs) |

All fetches use the public GitHub API and `raw.githubusercontent.com` at build time only; the published site still
makes no third-party request.

## The new repository

- Public, GPL-3.0 like the software; the same `SECURITY.md`, AI-disclosure workflow and templates, Renovate
  configuration (digest pins, uvx pins), CodeQL, zizmor, branch protection with required checks, code scanning at zero.
- `ghcr.io/openwhistle/website` is published from the new repository; the cosign identity changes to
  `https://github.com/openwhistle/website/.github/workflows/website-image.yml@refs/heads/main`, so the deploy side's
  verification is updated in the same step (wdk-ansible).
- The deploy needs no secret: wdk-ansible's Renovate follows the image's digest, whichever repository publishes it.

## Guards

Each goes through the mutation audit.

| Guard | Catches |
| --- | --- |
| `config.yml` = `Settings` of the release tag, both directions | an undocumented or stale setting |
| Status values and admin routes in the docs = the tag's source | a release whose guide describes the old workflow |
| Fonts and mark byte-identical to the tag's | the site and the app drifting apart visually |
| Weekly run of the website workflow | a release left undocumented for more than a week |
| App repository: no file under `docs/` and no test reading `docs/` remains | a half-moved site |

## Out of scope

Rewriting any page; a second documentation version per release (the site documents the latest release only); moving
the app's own `docs-tech/`.
